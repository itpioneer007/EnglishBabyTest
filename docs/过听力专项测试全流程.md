# 过听力专项测试全流程（自动化）

> 本文描述「听力专项」模块「测试」部分的完整自动化流程，含入口、答题循环、题型分流与踩坑记录。
> 入口脚本：`scripts/modules/听力专项.py`（`run_module(d)` / `python modules/听力专项.py`）。
> 坐标全部走 `S()/S_h()/S_w()`（基准 1080×2400）动态换算。

---

## 一、整体流程

```
主页 → 专项突破 → 听力专项
  → 「测试」Tab
  → 去答题 → 「好的我知道啦」→ 开始答题
  → 答题循环（共 17 题）
  → 查看报告 → back（回到测试列表）
```

- 练习部分（基础巩固→综合进阶→难点突破）与测试部分相互独立；本文聚焦**测试**。
- 测试默认先跑 U1（可用环境变量 `YYB_UNIT_FROM/YYB_UNIT_TO` 指定单元范围）。

---

## 二、启动与关广告

- 启动前确认设备连接（`u2.connect()`，序列号写 `ANDROID_SERIAL` 或用 `common/device.py`）。
- **关广告必须用项目既有正确流程**（`scheduler.py` 里的方式）：
  先轮询等广告出现（最多约 6s）→ `dismiss_global_popups()` ×2 → `close_ad()` ×2。
  ⚠ 广告是 `app_start` 后延迟 4~6s 才加载，**单次过早 `close_ad()` 会点错进入别的界面导致提前结束**。

---

## 三、答题循环（核心）

每题统一进入 `_test_answer_loop(d, max_q=30)`，逐题：

1. `dump_hierarchy()` 取当前界面 XML。
2. **排序题优先判断**（放在单选/判断之前，避免被误判）：
   - 含 `img_sort_btn` → 图片排序（模式 A）→ `engine._handle_sort_question(d, {})`。
   - 题干含「排序」且无大图 → 方框排序（模式 B）→ 同样走 `engine._handle_sort_question(d, {})`。
3. 否则按题型分流：选择（A/B/C/D）、判断（T/F，注意 `clickable=false`）、填空（FastInputIME 注入）。
4. 每题答完点「检查/检测」；答错点「下一题」继续，**绝不遇到「查看报告」就提前退出**（最后一题才出报告）。
5. 总题数从右上角 `X/Y` 读取，据此判断是否还有下一题。

## 四、测试中的两种排序题（重点）

### 第 16 题 · 图片排序（模式 A）
- 5 张大图卡片（宽 300~700）+ 底部图片槽。
- 依次点 5 张大图 → 序号自动填入 → 点「检查」。
- 详见《不同题型答题的解决办法》第 1 节。

### 第 17 题 · 方框排序（模式 B，最后一题）
- 5 个方框（宽 ~228），左侧 `new_tv_sort` 是句子自带序号（非点击目标）。
- 点第一个方框激活 → 底部出序号 1~5 → 按位置顺序点 1→2→3→4→5。
- **关键**：点完序号 1 后「检查」出现、序号栏整体上移 → 每次重新检测位置再点下一个。
- 序号按钮可复用（点击不消失，App 顺序填 1~5），5 个方框填满即完成，「检查」已出现按需点击。
- 详见《不同题型答题的解决办法》第 2 节。

## 五、已修复的历史 Bug（备忘）

| Bug | 现象 | 修复 |
|-----|------|------|
| T/F 匹配不到 | `clickable=false` 的 CheckBox 无法匹配 | 整节点单独取 `text` 匹配 `T/F` |
| 图片排序误判单选 | 要求 `clickable=true` 匹配不到图片 `LinearLayout` | 只校验 `bounds` 在选项区，去掉 `clickable` 要求 |
| 排序题路由错 | Q17 含「排序」无 `img_sort_btn` 被错路由到圆圈排序 | Q16/Q17 统一走 `_handle_sort_question` |
| 方框排序过早停止 | 填 1 个序号检测到「检查」就 `break` | 必须填满 5 个序号后才点检查 |
| 关广告时机错 | 单次过早 `close_ad()` 点进别的界面 | 改用 `scheduler` 轮询+两次关闭 |
| 序号栏坐标错位 | 预先快照旧坐标，点完序号 1 上移后错位 | 每次点完重新检测序号按钮位置 |
