## 一、数据结构（三人共享）

### 1.1 `_review_item` — 单题6维审查结果 ← 核心变更

**生产者：B同学**（巡检模块）+ **A同学**（提供5/6/8维检查函数）
**消费者：C同学**（导出）

```json
{
    "qid": "新湘鲁六上-U6-Q03",
    "idx": 3,
    "total": 14,
    "question_type": "听音选择词汇",
    "screenshot": "q03.png",
    "stem": "英语课上，老师在播放...",
    "recording": "This student is helpful.",
    "script_answer": "B",
    "is_audio_question": false,

    "ai_stem": false,
    "ai_content": false,
    "ai_image": true,
    "ai_answer": true,
    "ai_post_error": null,
    "ai_audio": null,
    "ai_report": null,

    "stem_reason": "...",
    "content_reason": "...",
    "image_reason": "...",
    "answer_reason": "...",
    "post_error_reason": "",
    "audio_reason": "",
    "report_reason": "",

    "overall_passed": false,
    "overall_score": 0.5,
    "error_dimensions": ["stem", "content"],
    "timestamp": "2026-07-28T17:00:00"
}
```

**字段说明：**
- `ai_post_error` — A1实现：答错后检查通过=True，不通过=False，非触发条件=null
- `ai_audio` — A2实现：听力题音频检查通过=True，不通过=False，非听力题=null
- `ai_report` — A3实现：模块完成报告检查，仅最后一题时有值
- `error_dimensions` — 汇总所有不通过的维度名列表（供C快速筛选）

这是审查完成后每道题的基本数据，存于 `data/inspection_state.json` 的 `questions` 字段。

**生产者：B同学**（批量调度的巡检模块）
**消费者：A同学**（溯源）、**C同学**（导出）

```json
{
    "qid": "新湘鲁六上-U6-Q03",
    "idx": 3,
    "total": 14,
    "question_type": "听音选择词汇",
    "screenshot": "q03.png",
    "stem": "英语课上，老师在播放...",
    "recording": "This student is helpful.",
    "script_answer": "B",

    "ai_stem": false,
    "ai_content": false,
    "ai_image": true,
    "ai_answer": true,

    "stem_reason": "[不通过] | 题干文字与脚本不一致...",
    "content_reason": "[不通过] | 选项B显示为care...",
    "image_reason": "⏭ 非配图题",
    "answer_reason": "[通过] | 选项可点击...",

    "overall_passed": false,
    "overall_score": 0.5,
    "knowledge_check": {},

    "human_label": null,
    "human_note": "",
    "timestamp": "2026-07-28T17:00:00"
}
```

## 二、API 接口（三人各自的承诺）

### 2.1 A同学 — 溯源接口

| 方法 | 路径 | 输入 | 输出 |
|------|------|------|------|
| GET | `/api/trace/<qid>` | — | `_trace_detail` |
| GET | `/api/trace/list` | — | `{total, items: [{qid, failed_dims, ...}]}` |
| GET | `/api/trace/screenshot/<qid>/<dim>` | — | PNG 图片 |

### 2.2 B同学 — 批量接口

| 方法 | 路径 | 输入 | 输出 |
|------|------|------|------|
| POST | `/api/batch/start` | `{version, units, stages, docx}` | `{success, modules, eta}` |
| GET | `/api/batch/status` | — | `_batch_status` |
| POST | `/api/batch/pause` | — | `{success}` |
| POST | `/api/batch/resume` | — | `{success}` |
| POST | `/api/batch/cancel` | — | `{success}` |
| GET | `/api/batch/history` | — | `[{plan, results, ...}]` |

### 2.3 C同学 — 导出接口

| 方法 | 路径 | 输入 | 输出 |
|------|------|------|------|
| POST | `/api/export/html` | `{result_ids?}` | `{success, url, stats}` |
| POST | `/api/export/csv` | — | `{success, url, count}` |
| POST | `/api/export/screenshots` | — | `{success, url, count}` |
| GET | `/api/export/download/<filename>` | — | 文件二进制 |
| POST | `/api/export/email` | `{to?}` | `{success}` |
| GET/POST | `/api/export/config` | — / `_export_config` | 配置 |

## 四、Git 分支

```
main ───────────────────────────
  │
  ├── feat/trace   ← A 的代码 (2026-07-28)
  ├── feat/batch   ← B 的代码
  └── feat/export  ← C 的代码
```

**合并规则：**
- 每天至少合一次 main
- 改接口必须同步更新本文档
- 合之前确保 `python3 -c "from web_server import app"` 不报错

---

## 五、修改本文档的流程

1. 你需要用到一个还不存在的字段 → 先更新本文档 → 通知另外两人
2. 另外两人根据文档调整自己的代码
3. 合并时以文档为准
